# CLI agent factory (A2A)

Один узел — команда CLI-агентов. Оркестратор получает `task`, сам решает, кого запустить, и общается с подчинёнными через инструменты `a2a_*`. Узел завершается, когда оркестратор закончил; его ответ уходит в `text`, остальное — в `meta`.

## Входы

| Name | Назначение | Default |
| --- | --- | --- |
| `task` | Задание оркестратору | — |
| `orchestrator` | slug корневого агента | `opencode` |
| `profiles` | Роли от цепочки `plugin.cli-agent.agent-profile` | — |
| `roster` | JSON-массив slug, которых агенты могут запускать с attach фабрики | `[orchestrator]`, если нет и профилей |
| `models` | JSON `{ "cursor": "sonnet-4.6" }` для Cursor / Codex / Claude Code | модель по умолчанию CLI |
| `llmConfig`, `mcpAttach`, `skillAttach`, `rulesAttach` | Оркестратору и агентам из `roster`; `llmConfig` — ещё и ролям без своего | — |
| `maxAgents` | Всего агентов, включая оркестратора (1–32) | 6 |
| `maxDepth` | Уровней делегирования (0–5); 0 — оркестратор без `a2a_spawn` | 2 |
| `agentTimeoutMs` | Таймаут одного контейнера | 10 мин |
| `budgetMs` | Таймаут всей команды (до 2 ч); по истечении команда отменяется | 30 мин |
| `waitSliceMs` | Сколько держится один вызов `a2a_wait` / `a2a_ask_parent` (5–110 с) | 45 с |

## Роли

Профиль задаёт имя роли, CLI-агента, описание и собственные `mcpAttach`, `skillAttach`, `rulesAttach`, `model`. Оркестратор видит роли с описаниями и запускает их через `a2a_spawn` по имени. Имена ролей уникальны; `orchestrator` зарезервировано.

## Выходы

| Name | Описание |
| --- | --- |
| `text` | Ответ оркестратора |
| `status` | `ok`, `error` (оркестратор упал, отменён или вышел бюджет), `unsupported` (неверная конфигурация) |
| `meta` | JSON: `agents`, `calls`, `graph`, `totals`, `limits` |

## Инструменты агента

MCP-сервер `a2a` добавляется к `mcpAttach` каждого агента:

| Tool | Кому | Что делает |
| --- | --- | --- |
| `a2a_spawn` | глубина < `maxDepth` | Запускает агента из ростера; возвращает `working`, `input-required`, `completed` или `failed` |
| `a2a_wait` | глубина < `maxDepth` | Ждёт запущенного агента ещё одно окно |
| `a2a_reply` | глубина < `maxDepth` | Отвечает на вопрос запущенного агента |
| `a2a_ask_parent` | все, кроме оркестратора | Вопрос родителю; у родителя задача переходит в `input-required` |
| `a2a_send` / `a2a_inbox` | все | Записки любому живому агенту по id и чтение своих |

Когда агент завершается, его ещё работающие потомки отменяются, а контейнеры убиваются.

## `meta`

- `agents[]` — `id`, `role`, `slug`, `parentId`, `depth`, `state`, превью задачи и результата, `latencyMs`, `usage`, `metrics` (как `metricsJson` у CLI-агента)
- `calls[]` — лента событий: `spawn`, `ask`, `reply`, `message`, `result`, `cancel` с `from`, `to`, `atMs`
- `graph` — узлы и агрегированные рёбра `from → to` по виду вызова
- `totals` — число агентов по состояниям, глубина, счётчики вызовов, токены (если usage известен у всех агентов)

## Сеть

Агенты обращаются к хабу сайдкара `cli-agent` по `CLI_AGENT_A2A_URL` (default `http://host.docker.internal:9419`). Хаб слушает `CLI_AGENT_A2A_PORT` (default 9419); порт публикуется на хосте. Каждый агент получает свой токен; токен действует, пока агент работает.

В `orchestrator`, `roster` и профилях допустимы только агенты с MCP-клиентом; `aider` и `pi` в команду не входят.
